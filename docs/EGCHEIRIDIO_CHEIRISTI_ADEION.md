# Εγχειρίδιο Χειριστή Αδειών

**Σύστημα:** ΠΔΕΔΕ — Διαχείριση Αιτήσεων Άδειας  
**Διεύθυνση παραγωγής:** https://adeies.pdede.gov.gr  
**Δοκιμές (staging):** https://sadeies.pdede.gov.gr  
**Κοινό:** Χειριστές τμήματος αδειών (`LEAVE_HANDLER`)  
**Έκδοση οδηγού:** Ιούλιος 2026  
**Ευρετήριο όλων των ρόλων:** [README.md](README.md)

Το εγχειρίδιο περιγράφει τι βλέπετε σε κάθε κατάσταση αίτησης, τι πρέπει να κάνετε από την αρχή έως το τέλος, τις ειδικές περιπτώσεις (ΚΕΔΑΣΥ, αναρρωτικές, ανάκληση άδειας, αναπληρωτές, υπόλοιπα), τις **νέες εγγραφές χρηστών**, τις **αναφορές** (συμπ. εξαγωγή SCH) και troubleshooting.

---

## 1. Ρόλος και βασικές οθόνες

### Τι κάνει ο χειριστής
- Παραλαμβάνει αιτήσεις μετά την έγκριση προϊσταμένου (ή απευθείας όταν δεν απαιτείται έγκριση).
- Καταχωρεί πρωτόκολλο ΠΔΕΔΕ / ΣΗΔΕ.
- Ζητά ή ελέγχει δικαιολογητικά.
- Ετοιμάζει απόφαση PDF, προωθεί προς υπογραφές, ανεβάζει ακριβές αντίγραφο ΣΗΔΕ και ολοκληρώνει.
- Διαχειρίζεται υπόλοιπα κανονικών, ετήσια ανανέωση, συμβάσεις αναπληρωτών, σύνολα αναρρωτικών.
- **Ενεργοποιεί νέους χρήστες** μετά την εγγραφή μέσω ΠΣΔ (Νέες Εγγραφές Χρηστών).
- Τρέχει **αναφορές** (προϊστάμενοι τμημάτων, παρουσιολόγιο, εξαγωγή για SCH).
- Απορρίπτει αιτήσεις όταν χρειάζεται (με αιτιολογία).

### Τι **δεν** κάνει ο χειριστής
- Δεν εγκρίνει ως προϊστάμενος αιτήσεις υφισταμένων (εκτός αν έχει και ρόλο/αρμοδιότητα προϊσταμένου για συγκεκριμένο τμήμα).
- Δεν πρωτοκολλεί ΚΕΔΑΣΥ/ΚΕΠΕΑ (το κάνει γραμματεία / αρμόδιος ΚΕΔΑΣΥ).
- Δεν εγκρίνει **δική του** αίτηση ως προϊστάμενος — εγκρίνει ο ανώτερός του.
- Δεν δημιουργεί χρήστες από τα «Βασικά Στοιχεία» (εκεί μόνο επεξεργασία υπαρχόντων).

### Κύριες οθόνες
| Οθόνη | Χρήση |
|--------|--------|
| Dashboard χειριστή | Ουρά αιτήσεων, φίλτρα, ειδοποιήσεις νέων εγγραφών |
| Προβολή αίτησης | Πλήρη στοιχεία, συνημμένα, κλείδωμα, ιστορικό |
| Νέες Εγγραφές Χρηστών | Έλεγχος / ενεργοποίηση χρηστών από ΠΣΔ |
| Ιστορικό υπολοίπου (ledger) | Κινήσεις κανονικών αδειών |
| Ετήσια ανανέωση | 1/1: λήξη / μεταφορά / νέο δικαίωμα |
| Συμβάσεις αναπληρωτών | Λήξη / νέα σύμβαση / επανεμφανίσεις |
| Αναφορές | Προϊστάμενοι τμημάτων · Παρουσιολόγιο · Εξαγωγή για SCH |
| Βασικά στοιχεία βάσης | Πίνακες αναφοράς (τύποι αδειών, τμήματα κ.λπ.) |

## 2. Καταστάσεις αίτησης (status) — γλωσσάρι

| Κωδικός | Εμφάνιση | Ποιος ενεργεί κυρίως |
|---------|----------|----------------------|
| `DRAFT` | Πρόχειρη αίτηση | Αιτών |
| `SUBMITTED` | Υποβληθείσα αίτηση | Προϊστάμενος |
| `PENDING_KEDASY_PROTOCOL` | Εκκρεμεί Πρωτόκολλο ΚΕΔΑΣΥ/ΚΕΠΕΑ | Γραμματεία / ΚΕΔΑΣΥ |
| `PENDING_PROTOCOL` | Για πρωτόκολλο ΠΔΕΔΕ | **Χειριστής** |
| `IN_REVIEW` | Σε επεξεργασία από τμήμα αδειών | **Χειριστής** |
| `WAITING_FOR_DOCUMENTS` | Σε αναμονή δικαιολογητικών | Αιτών + **Χειριστής** |
| `DECISION_PREPARATION` | Ετοιμασία απόφασης | **Χειριστής** |
| `PENDING_YC_COMMITTEE` | Αναμονή απόφασης Υγειονομικής Επιτροπής | **Χειριστής** (μετά την επιστροφή) |
| `PENDING_SIGNATURES` | ΣΗΔΕ — προς υπογραφές | **Χειριστής** |
| `COMPLETED` | Ολοκληρώθηκε | — (τερματικό) |
| `REVOKED_BY_REQUEST` | ΑΝΑΚΛΗΣΗ ΑΔΕΙΑΣ ΑΠΟ ΑΙΤΗΣΗ | — (τερματικό γονικής) |
| `SUPERVISOR_REJECTED` | Αρνητική έγκριση προϊσταμένου | — |
| `REJECTED_BY_LEAVES_DEPT` | Απόρριψη από τμήμα αδειών | — |
| `CANCELLED_BY_APPLICANT` | Ανάκληση από αιτούντα | — |

### Σημαντικός διαχωρισμός
- **Ανάκληση αίτησης** = ο αιτών ακυρώνει αίτηση που **δεν** έχει ολοκληρωθεί → `CANCELLED_BY_APPLICANT`.
- **Ανάκληση άδειας** = νέα αίτηση που ακυρώνει (ολικά/μερικά) μια **ολοκληρωμένη** άδεια. Η γονική μπορεί να γίνει `REVOKED_BY_REQUEST`.

## 3. Διάγραμμα βασικής ροής

```text
Αιτών: DRAFT → υποβολή
        │
        ├─(ΚΕΔΑΣΥ/ΚΕΠΕΑ/ΣΔΕΥ κατά περίπτωση)→ PENDING_KEDASY_PROTOCOL → (γραμματεία) →
        │
        ├─(απαιτεί έγκριση)→ SUBMITTED → (προϊστάμενος ΕΓΚΡΙΣΗ) → PENDING_PROTOCOL
        │                 └→ SUPERVISOR_REJECTED (τέλος)
        │
        └─(χωρίς έγκριση)→ PENDING_PROTOCOL

Χειριστής:
  PENDING_PROTOCOL → καταχώρηση πρωτ. ΠΔΕΔΕ → IN_REVIEW
       │
       ├→ αίτημα δικαιολογητικών → WAITING_FOR_DOCUMENTS → πίσω IN_REVIEW ή DECISION_PREPARATION
       ├→ Υγειονομική (αναρρωτικές) → PENDING_YC_COMMITTEE → DECISION_PREPARATION
       ├→ ετοιμασία απόφασης → DECISION_PREPARATION → ΠΡΟΣ ΥΠΟΓΡΑΦΕΣ → PENDING_SIGNATURES
       │                              → upload ακριβούς αντιγράφου → ΟΛΟΚΛΗΡΩΣΗ → COMPLETED
       └→ (συντόμευση) ΟΛΟΚΛΗΡΩΣΗ από IN_REVIEW όταν επιτρέπεται / απλές περιπτώσεις
```

## 4. Τι κάνει ο χειριστής σε κάθε status

### 4.1 `PENDING_PROTOCOL` — Για πρωτόκολλο ΠΔΕΔΕ

**Πότε φτάνει εδώ:** Μετά έγκριση προϊσταμένου, ή απευθείας αν ο τύπος άδειας δεν απαιτεί έγκριση, ή μετά πρωτόκολλο ΚΕΔΑΣΥ.

**Ενέργειες σας:**
1. **Προβολή** αίτησης — ελέγξτε στοιχεία, διαστήματα, συνημμένα, PDF αίτησης.
2. **Αποστολή PDF** στο πρωτόκολλο (αν χρειάζεται επανάληψη / απέτυχε το αυτόματο).
3. **Καταχώρηση πρωτοκόλλου** ΠΔΕΔΕ (αριθμός, ημερομηνία, σχόλια) → μετάβαση σε `IN_REVIEW`.
4. **Απόρριψη** (με υποχρεωτική αιτιολογία) αν η αίτηση δεν προχωρά.

**Προσοχή:** Αν εμφανιστεί ειδοποίηση αποτυχίας αυτόματου email πρωτοκόλλου, δηλώστε «Έλαβα γνώση» και ξαναστείλτε το PDF χειροκίνητα αν χρειάζεται.

---

### 4.2 `IN_REVIEW` — Σε επεξεργασία

**Εδώ γίνεται η ουσιαστική δουλειά του τμήματος αδειών.**

**Ενέργειες σας (ανά περίπτωση):**

| Ενέργεια | Πότε |
|----------|------|
| **Αίτημα δικαιολογητικών** | Λείπουν έγγραφα → `WAITING_FOR_DOCUMENTS` |
| **Επιστροφή** | Επιστροφή στον αιτούντα / προηγούμενο βήμα (όπως ορίζεται στην οθόνη) |
| **Διαβιβαστικό ΥΕ** | Αναρρωτική με υπέρβαση ορίου ημερών → `PENDING_YC_COMMITTEE` |
| **Ετοιμασία απόφασης** | Έτοιμοι για κείμενο/PDF απόφασης → `DECISION_PREPARATION` (ή παραμένετε σε επεξεργασία απόφασης) |
| **Ολοκλήρωση** | Όταν η διαδικασία επιτρέπει άμεση ολοκλήρωση (π.χ. χωρίς ΣΗΔΕ / απλή διαδρομή). Για κανονική με απόφαση ΣΗΔΕ προτιμήστε την πλήρη ροή υπογραφών. |
| **Απόρριψη** | Με αιτιολογία |

**Κανονική άδεια:** Στην ολοκλήρωση αφαιρούνται αυτόματα ημέρες από το υπόλοιπο (ledger). Αν σας ζητηθεί «υπόλοιπο μετά», συμπληρώστε προσεκτικά.

**Κλείδωμα:** Μπορείτε να κλειδώσετε την αίτηση όσο την επεξεργάζεστε (timeout ~30 λεπτά) ώστε να μην την αλλάζει άλλος χειριστής ταυτόχρονα.

---

### 4.3 `WAITING_FOR_DOCUMENTS` — Αναμονή δικαιολογητικών

**Ενέργειες σας:**
1. **Αποστολή email** στον υπάλληλο με τις απαιτήσεις / υπενθύμιση.
2. **Παροχή δικαιολογητικών** (ανέβασμα από εσάς αν τα έχετε).
3. Ο αιτών μπορεί να ανεβάσει αρχεία και να δηλώσει ολοκλήρωση αποστολής.
4. Μετά την παραλαβή: επιστροφή σε επεξεργασία / συνέχεια προς απόφαση.
5. **Απόρριψη** ή **Επιστροφή** αν χρειάζεται.

**Σημείωση:** Η προθεσμία δικαιολογητικών είναι ενημερωτική· δεν απορρίπτεται αυτόματα η αίτηση όταν λήξει.

---

### 4.4 `PENDING_YC_COMMITTEE` — Υγειονομική Επιτροπή

**Πότε:** Από `IN_REVIEW`, για τύπο αναρρωτικής που μετρά στο σύνολο, όταν ο υπάλληλος υπερβαίνει το όριο ημερών έτους (συνήθως > 8).

**Ενέργειες σας:**
1. Περιμένετε την απόφαση ΥΕ εκτός συστήματος (όπως η υπηρεσιακή διαδικασία).
2. Στην εφαρμογή: **Απόφαση ΥΕ** / παραλαβή → μετάβαση σε `DECISION_PREPARATION`.
3. Μετά συνεχίζετε με ετοιμασία απόφασης άδειας όπως συνήθως.

**Προσοχή:** Από αυτή την κατάσταση ο αιτών **δεν** μπορεί να κάνει ανάκληση αίτησης. Αν κολλήσει, πρέπει να καταχωρηθεί η επιστροφή από ΥΕ.

---

### 4.5 `DECISION_PREPARATION` — Ετοιμασία απόφασης

**Ενέργειες σας:**
1. **Επεξεργασία απόφασης** — πρότυπα (λογότυπο, πληροφορίες, υπογράφων, κείμενο).
2. Δημιουργία / αποθήκευση **PDF απόφασης**.
3. Όταν υπάρχει PDF: **Προς υπογραφές** → `PENDING_SIGNATURES`.
4. **Απόρριψη** αν δεν προχωρά.

Ο αιτών σε αυτή τη φάση **μπορεί** ακόμη να ανακαλέσει την αίτηση.

---

### 4.6 `PENDING_SIGNATURES` — ΣΗΔΕ προς υπογραφές

**Ενέργειες σας:**
1. Η απόφαση υπογράφεται στο ΣΗΔΕ (εκτός εφαρμογής).
2. **Upload τελικής / ακριβές αντίγραφο** του υπογεγραμμένου PDF στην αίτηση.
3. Όταν υπάρχει ακριβές αντίγραφο: **Ολοκλήρωση** → `COMPLETED`.
4. Μπορείτε ακόμη να επεξεργαστείτε την απόφαση ή να **απορρίψετε**.

Με την ολοκλήρωση:
- Κανονική άδεια → αφαίρεση ημερών στο ledger.
- Αναρρωτική (σύνολο) → ενημέρωση ημερών έτους και συνόλου πενταετίας.

---

### 4.7 Τερματικές καταστάσεις

| Status | Τι σημαίνει για εσάς |
|--------|----------------------|
| `COMPLETED` | Τέλος επιτυχούς ροής. Ο αιτών μπορεί να ξεκινήσει **Ανάκληση άδειας**. |
| `REVOKED_BY_REQUEST` | Η αρχική άδεια ανακλήθηκε πλήρως μέσω αίτησης ανάκλησης. Δεν μετρά ως ενεργή χορήγηση. |
| `REJECTED_BY_LEAVES_DEPT` | Απορρίφθηκε από εσάς. |
| `SUPERVISOR_REJECTED` | Απέρριψε ο προϊστάμενος πριν φτάσει σε εσάς. |
| `CANCELLED_BY_APPLICANT` | Ο αιτών ανακάλεσε την **αίτηση** (όχι την ολοκληρωμένη άδεια). |

Σε όλες τις παραπάνω: κυρίως **Προβολή**.

---

### 4.8 Καταστάσεις εκτός ουράς χειριστή (για ενημέρωσή σας)

| Status | Ποιος ενεργεί | Σχόλιο |
|--------|----------------|--------|
| `DRAFT` | Αιτών | Δεν εμφανίζεται ως προς επεξεργασία. |
| `SUBMITTED` | Προϊστάμενος | Αν «κολλάει», συχνά λείπει εγκρίνων (βλ. troubleshooting). |
| `PENDING_KEDASY_PROTOCOL` | Γραμματεία ΚΕΔΑΣΥ/ΚΕΠΕΑ | Εσείς **δεν** καταχωρείτε αυτό το πρωτόκολλο και **δεν** απορρίπτετε από εδώ. Ο αιτών μπορεί να ανακαλέσει την αίτηση. |

## 5. Πλήρη σενάρια από την αρχή έως το τέλος

### 5.1 Κανονική άδεια (τυπική διαδρομή ΠΔΕΔΕ)

1. Υπάλληλος δημιουργεί αίτηση → υποβολή.
2. Προϊστάμενος εγκρίνει → `PENDING_PROTOCOL`.
3. Εσείς: πρωτόκολλο ΠΔΕΔΕ → `IN_REVIEW`.
4. Ετοιμασία απόφασης → προς υπογραφές → upload ακριβούς αντιγράφου → ολοκλήρωση.
5. Έλεγχος: υπόλοιπο μειώθηκε, εγγραφή ledger «χορήγηση».

### 5.2 Άδεια χωρίς έγκριση προϊσταμένου

1. Υποβολή → απευθείας `PENDING_PROTOCOL`.
2. Συνεχίζετε όπως στο 5.1 από το πρωτόκολλο.

### 5.3 Άτυπη / απλή άδεια (`is_simple`)

- Συχνά ολοκληρώνεται με την έγκριση προϊσταμένου (χωρίς πλήρη κύκλο ΣΗΔΕ).
- Ελέγξτε στην προβολή αν έχει ήδη `COMPLETED` πριν επέμβετε.

### 5.4 ΚΕΔΑΣΥ / ΚΕΠΕΑ / ΣΔΕΥ

1. Υποβολή → συχνά `PENDING_KEDASY_PROTOCOL`.
2. Γραμματεία καταχωρεί πρωτ. ΚΕΔΑΣΥ/ΚΕΠΕΑ → μετά `SUBMITTED` ή `PENDING_PROTOCOL` ανά κανόνα.
3. Προϊστάμενος (συχνά ΚΕΔΑΣΥ για ΣΔΕΥ) εγκρίνει.
4. Μετά μπαίνει στην ουρά σας (`PENDING_PROTOCOL`) όπως οι υπόλοιπες.

### 5.5 Αναρρωτική με ΥΔ

- Όριο: συνήθως **2 αιτήσεις/έτος** (ολοκληρωμένες).
- Αν ο υπάλληλος έχει εξαντλήσει το όριο, η υποβολή αποτυγχάνει με μήνυμα.
- Η ροή έγκρισης/πρωτοκόλλου/απόφασης είναι ίδια με άλλες άδειες που απαιτούν επεξεργασία.

### 5.6 Αναρρωτική που μετρά στο σύνολο (+ Υγειονομική)

1. Κανονική ροή έως `IN_REVIEW`.
2. Αν οι ημέρες έτους υπερβαίνουν το όριο: εμφανίζεται **Διαβιβαστικό ΥΕ**.
3. Στέλνετε σε ΥΕ → περιμένετε → καταχωρείτε επιστροφή → ετοιμασία απόφασης → υπογραφές → ολοκλήρωση.
4. Ελέγξτε ενημέρωση ημερών τρέχοντος έτους και συνόλου πενταετίας.

### 5.7 Ανάκληση άδειας (ολική / μερική)

**Προϋπόθεση:** Αρχική άδεια σε `COMPLETED`, χωρίς άλλη ανοιχτή αίτηση ανάκλησης.

1. Ο αιτών (ή εσείς για λογαριασμό του, αν ισχύει) πατά **Ανάκληση άδειας**.
2. Επιλέγει Ολική ή Μερική, διαστήματα, προεπισκόπηση, υποβολή.
3. Η **νέα** αίτηση ακολουθεί **ίδιο workflow** με κανονική αίτηση (έγκριση → πρωτόκολλο → απόφαση → ολοκλήρωση).
4. Στην ολοκλήρωση της ανάκλησης:
   - Αν η αρχική επηρέαζε υπόλοιπο κανονικών → **επιστρέφονται** ημέρες στο ledger (`LEAVE_REVOKED`).
   - Ολική (ή άθροισμα μερικών που καλύπτουν όλες τις ημέρες) → γονική `REVOKED_BY_REQUEST`.
   - Μερική → γονική μένει `COMPLETED` με ένδειξη ανακληθεισών ημερών.

**Μην** δημιουργείτε ανάκληση από το dropdown «Νέα αίτηση» — ο τύπος ανάκλησης δεν εμφανίζεται εκεί σκόπιμα.

### 5.8 Δημιουργία αίτησης για άλλον χρήστη

Από λίστα χρηστών / ιστορικό: μπορείτε να δημιουργήσετε αίτηση για υπάλληλο.  
Αν είναι αναπληρωτής σε αναμονή σύμβασης, θα μπλοκαριστεί μέχρι να καταχωρήσετε νέα σύμβαση.

## 6. Υπόλοιπα κανονικών αδειών (ledger)

### Τι να γνωρίζετε
- Κάθε ολοκλήρωση κανονικής αφαιρεί ημέρες (FIFO: πρώτα μεταφερόμενο, μετά τρέχον).
- Κάθε ολοκλήρωση ανάκλησης επιστρέφει ημέρες (στον κουβά τρέχοντος).
- Χειροκίνητη διόρθωση / αλλαγή δικαιούμενων γίνεται με σχόλιο και φαίνεται στο ιστορικό.

### Ετήσια ανανέωση (διοικητικοί / εκπαιδευτικοί)
1. Ανοίξτε **Ετήσια ανανέωση**.
2. Ανανεώστε τη λίστα / ελέγξτε προεπισκόπηση ανά χρήστη.
3. Ειδοποιήστε χρήστες αν χρειάζεται.
4. **Εφαρμόστε** την ανανέωση (λήξη παλαιού μεταφερόμενου → μεταφορά τρέχοντος → χορήγηση νέου δικαιώματος).

**Η 1/1 δεν τρέχει αυτόματα.** Αν δεν πατήσετε εφαρμογή, τα υπόλοιπα δεν αλλάζουν.

### Αναπληρωτές
1. Οθόνη **Συμβάσεις αναπληρωτών** (`/leaves/substitute-contracts/`).
2. Καρτέλες που θα δείτε συνήθως:
   - **Προς λήξη** — συμβάσεις που πλησιάζουν στο τέλος
   - **Σε αναμονή νέας σύμβασης** — μηδενισμένοι, χωρίς δικαίωμα νέας αίτησης
   - **Επανεμφανίστηκαν** — συνδέθηκαν ξανά χωρίς ενεργή σύμβαση (ειδοποίηση για εσάς)
   - **Ιστορικό** — παλιές κινήσεις
3. **Λήξη** (π.χ. 30/6) ή **μαζική λήξη**: μηδενισμός υπολοίπου, κατάσταση αναμονής, δεν υποβάλλουν αιτήσεις.
4. **Νέα σύμβαση** (π.χ. 1/9): ορισμός δικαιούμενων / αρχικού υπολοίπου.
5. Χωρίς ενεργή σύμβαση ο αναπληρωτής **δεν** μπορεί να υποβάλει άδεια (ούτε εσείς για λογαριασμό του).

Για οδηγίες προς τον ίδιο τον αναπληρωτή: [Παράρτημα Αναπληρωτή](EGCHEIRIDIO_ANAPLIROTI.md).

## 7. Νέες εγγραφές χρηστών (ΠΣΔ)

Οι νέοι χρήστες **δεν** δημιουργούνται από τα Βασικά Στοιχεία. Η κανονική ροή:

1. Ο υπάλληλος συνδέεται στο **adeies.pdede.gov.gr** με ΠΣΔ και συμπληρώνει τη φόρμα στοιχείων.
2. Εμφανίζεται στην ουρά **Νέες Εγγραφές Χρηστών** (`/leaves/pending-registrations/`) — και με ειδοποίηση στο dashboard σας.
3. Ανοίγετε την εγγραφή → ελέγχετε/συμπληρώνετε:
   - Τμήμα, ειδικότητα
   - **Τύπο υπαλλήλου** (υποχρεωτικό)
   - **Ρόλους** (≥1, συνήθως Υπάλληλος)
   - Δικαίωμα αίτησης άδειας (αποεπιλογή σε ειδικές περιπτώσεις)
   - Αρ. μητρώου SCH (`employee_number`) — έρχεται από ΠΣΔ· κρίσιμο για την εξαγωγή SCH
4. **Ενεργοποίηση** → ο χρήστης γίνεται ενεργός και λαμβάνει email.
5. Προαιρετικά: **Έλαβα γνώση** για την ειδοποίηση· επεξεργασία προτύπου email έγκρισης από την ίδια ενότητα.

**Προσοχή:**
- Αν κάποιος έκανε μόνο σύνδεση ΠΣΔ χωρίς να ολοκληρώσει τη φόρμα, **δεν** εμφανίζεται στη λίστα.
- Η «Απόρριψη» από τη λίστα χειριστή **διαγράφει** τον χρήστη (δεν είναι απλή απόρριψη status).
- Αν ο χρήστης θα είναι **προϊστάμενος**, μετά την ενεργοποίηση ορίστε τον και στο πεδίο **Προϊστάμενος** του τμήματος (Βασικά Στοιχεία → Τμήματα). Ο ρόλος `MANAGER` μόνος του δεν αρκεί για σωστή ιεραρχία εγκρίσεων.
- Αν είναι **αναπληρωτής**, καταχωρήστε σύμβαση πριν περιμένετε αιτήσεις.

## 8. Αναφορές

Μενού **Αναφορές** (`/leaves/reports/`) — διαθέσιμο σε χειριστές / διαχειριστές αδειών:

| Αναφορά | Τι κάνει |
|---------|----------|
| **Προϊστάμενοι ανά Τμήμα** | Ελέγχει ποια τμήματα έχουν ορισμένο προϊστάμενο (FK) και ποια όχι |
| **Παρουσιολόγιο** | Παρουσιολόγιο **Αυτοτελούς Διεύθυνσης** — εξαγωγή PDF / Excel |
| **Εξαγωγή για SCH** | Ολοκληρωμένες άδειες ΠΔΕΔΕ για αποστολή στο SCH — εξαγωγή Excel |

### Εξαγωγή για SCH — λεπτομέρειες

1. Ανοίξτε **Αναφορές → Εξαγωγή για SCH**.
2. Επιλέξτε περίοδο **Από / Έως** (βάσει **ημερομηνίας έναρξης** της άδειας).
3. Πατήστε Αναζήτηση · μετά **Excel**.

**Περιλαμβάνει μόνο:**
- Αιτήσεις σε κατάσταση **Ολοκληρώθηκε**
- Αιτούντες που **δεν** ανήκουν σε τμήματα τύπου ΚΕΔΑΣΥ / ΚΕΠΕΑ / ΣΔΕΥ

**Στήλες Excel:**
- Αρ. Μητρώου SCH  
- Ονοματεπώνυμο  
- Τύπος άδειας  
- Ημ/νία έναρξης  
- Εγκριθείσες ημέρες  
- Αρ. πρωτοκόλλου εισερχομένων (ΠΔΕΔΕ)  
- Ημ/νία πρωτοκόλλου εισερχομένων  

Αν λείπει αρ. μητρώου SCH σε χρήστη, διορθώστε στα στοιχεία χρήστη (Βασικά Στοιχεία / admin) πριν την οριστική εξαγωγή.

## 12. Troubleshooting

### Αίτηση «κολλημένη» σε `SUBMITTED`
**Αιτία:** Δεν βρίσκεται εγκρίνων προϊστάμενος (κενό τμήμα, κενός FK manager, ιεραρχία).  
**Τι να κάνετε:** Ελέγξτε τμήμα χρήστη και πεδίο «Προϊστάμενος» του τμήματος. Ενημερώστε διαχειριστή για διόρθωση δεδομένων. Ο αιτών μπορεί να ανακαλέσει την αίτηση αν επιτρέπεται.

### Κολλημένη σε `PENDING_KEDASY_PROTOCOL`
**Αιτία:** Δεν έχει καταχωρηθεί πρωτόκολλο ΚΕΔΑΣΥ/ΚΕΠΕΑ.  
**Τι να κάνετε:** Ειδοποιήστε γραμματεία/αρμόδιο. Εσείς δεν ολοκληρώνετε αυτό το βήμα. Ο αιτών μπορεί να ανακαλέσει την αίτηση.

### Κολλημένη σε `PENDING_YC_COMMITTEE`
**Αιτία:** Δεν καταχωρήθηκε επιστροφή από ΥΕ.  
**Τι να κάνετε:** Μόλις υπάρχει απόφαση ΥΕ, χρησιμοποιήστε την ενέργεια παραλαβής/απόφασης ΥΕ στην εφαρμογή.

### Κολλημένη σε `DECISION_PREPARATION`
**Αιτία:** Δεν δημιουργήθηκε PDF ή δεν προωθήθηκε προς υπογραφές.  
**Τι να κάνετε:** Επεξεργασία απόφασης → δημιουργία PDF → Προς υπογραφές. Εναλλακτικά απόρριψη με αιτιολογία.

### Κολλημένη σε `PENDING_SIGNATURES`
**Αιτία:** Λείπει το ακριβές αντίγραφο από ΣΗΔΕ.  
**Τι να κάνετε:** Upload τελικού υπογεγραμμένου PDF → Ολοκλήρωση.

### Αποτυχία αυτόματου email πρωτοκόλλου
**Τι να κάνετε:** Δηλώστε «Έλαβα γνώση» → ξαναστείλτε PDF με «Αποστολή PDF». Η αίτηση δεν χάνεται· προχωρά κανονικά μετά την καταχώρηση πρωτοκόλλου.

### Υπόλοιπο κανονικών δεν μειώθηκε μετά την ολοκλήρωση
**Έλεγχος:** Ο τύπος άδειας επηρεάζει υπόλοιπο κανονικών;  
**Τι να κάνετε:** Ανοίξτε ιστορικό υπολοίπου χρήστη. Αν λείπει εγγραφή, διορθώστε χειροκίνητα με σχόλιο και ενημερώστε τεχνική υποστήριξη.

### Υπόλοιπο δεν αυξήθηκε μετά ανάκληση άδειας
**Έλεγχος:** Ολοκληρώθηκε η **αίτηση ανάκλησης** (όχι μόνο δημιουργήθηκε); Η γονική ήταν κανονική που αφαιρεί υπόλοιπο;  
**Τι να κάνετε:** Ελέγξτε ledger για `LEAVE_REVOKED`. Αν λείπει, διόρθωση + ενημέρωση υποστήριξης.

### Αναπληρωτής δεν μπορεί να υποβάλει αίτηση
**Αιτία:** Κατάσταση αναμονής νέας σύμβασης μετά τη λήξη.  
**Τι να κάνετε:** Οθόνη συμβάσεων → καταχώρηση νέας σύμβασης.

### Μήνυμα εξάντλησης ΥΔ
**Αιτία:** Έχουν ολοκληρωθεί ήδη οι επιτρεπόμενες ΥΔ του έτους.  
**Τι να κάνετε:** Ενημερώστε τον υπάλληλο· δεν παρακάμπτεται από εσάς χωρίς αλλαγή πολιτικής/δεδομένων.

### Προϊστάμενος δεν μπορεί να εγκρίνει
**Πιθανές αιτίες:** Δεν είναι ο σωστός εγκρίνων του τμήματος· προσπαθεί να εγκρίνει δική του αίτηση· η αίτηση δεν είναι σε `SUBMITTED`.  
**Τι να κάνετε:** Επαληθεύστε `Department.manager` και ιεραρχία.

### Αλλαγή τμήματος χρήστη με ανοιχτή αίτηση
**Συμπεριφορά:** Ο εγκρίνων υπολογίζεται από το **τρέχον** τμήμα.  
**Τι να κάνετε:** Ενημερώστε παλιό/νέο προϊστάμενο· μην αφήνετε αιτήσεις μεσαία χωρίς επικοινωνία.

### Διπλή επεξεργασία από δύο χειριστές
**Τι να κάνετε:** Χρησιμοποιήστε κλείδωμα στην προβολή αίτησης.

### Λανθασμένες ημέρες αναρρωτικών πενταετίας
**Τι να κάνετε:** Από την αίτηση (αν υπάρχει φόρμα ενημέρωσης συνόλων) διορθώστε τα έτη· το σύστημα ξαναϋπολογίζει το σύνολο παραθύρου. Παλαιότερα έτη εκτός παραθύρου παραμένουν αποθηκευμένα αλλά δεν μετράνε στο σύνολο.

### Δεν εμφανίζεται «Ανάκληση άδειας»
**Έλεγχος:** Η άδεια είναι `COMPLETED`; Έχει μείνει υπόλοιπο ημερών προς ανάκληση; Υπάρχει ήδη ανοιχτή αίτηση ανάκλησης;  
**Τι να κάνετε:** Ολοκληρώστε ή ακυρώστε την ανοιχτή ανάκληση· μην ψάχνετε τον τύπο στο dropdown νέας αίτησης.

### Νέος χρήστης δεν φαίνεται στις Εγγραφές
**Αιτία:** Δεν ολοκλήρωσε τη φόρμα μετά το ΠΣΔ (`registration_submitted_at` κενό).  
**Τι να κάνετε:** Ζητήστε του να ξανασυνδεθεί και να ολοκληρώσει τη φόρμα στοιχείων.

### Εξαγωγή SCH χωρίς αρ. μητρώου
**Αιτία:** Δεν ήρθε / δεν αποθηκεύτηκε το `employee_number` από ΠΣΔ.  
**Τι να κάνετε:** Συμπληρώστε τον αρ. μητρώου στα στοιχεία χρήστη πριν την οριστική εξαγωγή.

### Προϊστάμενος τμήματος «λείπει» στην αναφορά
**Αιτία:** Δεν έχει οριστεί το πεδίο Προϊστάμενος στο τμήμα (FK), ακόμα κι αν κάποιος έχει ρόλο MANAGER.  
**Τι να κάνετε:** Βασικά Στοιχεία → Τμήματα → ορίστε Προϊστάμενο.
